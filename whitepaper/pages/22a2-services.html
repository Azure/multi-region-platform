Appendix A · Three services that need special attention

Storage, backup, and Key Vault across regions

Storage replication, backup and restore, and Key Vault illustrate why regional qualification cannot stop at “the service exists in both regions.”

Key Vault
Paired region
  • GRS and GZRS replicate data asynchronously to the service-defined secondary region.
  • Built-in geo-redundancy and failover behavior must be evaluated separately from workload-level recoverability; customer-managed failover is available, Microsoft-managed failover is a last resort.
Paired region
  • Cross Region Restore uses the paired region for supported data sources when vault replication and configuration are enabled.
  • Support and behavior differ by backup workload and configuration.
Paired region
  • In most paired regions, vault contents replicate asynchronously to the paired region.
  • Failover is Microsoft-initiated, best effort, and can occur only after significant delay; afterward the vault operates with restrictions, including read-only management. Workloads with tighter recovery objectives need an explicit multi-region design.
Region of choice
  • Object replication asynchronously replicates block blobs between selected accounts and regions — not append or page blobs, and not accounts with a hierarchical namespace (Data Lake Storage).
  • Requires change feed on the source and blob versioning on both; at most two destination accounts.
  • Shifts monitoring and failover to you; otherwise, application-level copy.
Region of choice
  • Determine which backup technologies and restore targets support the intended recovery region.
  • Azure Site Recovery supports Azure VM disaster recovery between Azure regions, subject to its support matrix; restricted-access regions can require explicit access approval.
  • Place backup vaults deliberately for the recovery region.
Region of choice
  • Some paired regions and all nonpaired regions do not use Microsoft-managed replication and failover. For the current list, see Reliability in Azure Key Vault on Microsoft Learn.
  • Use separate regional vaults or another supported custom multi-region design. Keys, secrets, and certificates each need their own recovery analysis: secrets and certificates can often be provisioned independently into regional vaults; customer-managed keys can have additional constraints.
  • Managed HSM offers optional two-region replication with both regions active. It applies to keys, not ordinary secrets and certificates; not every region can be an extended region, and it has its own cost.

Replicated data does not by itself make the workload recoverable. Validate the application recovery path end to end.

Demonstrate RTO and RPO through recovery testing, not configuration alone.

Often a runtime dependency: applications can require keys, secrets, and certificates simply to initialize, so data can be recoverable while the application still cannot start. See the next page.
