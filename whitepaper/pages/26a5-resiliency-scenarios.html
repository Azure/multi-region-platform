Appendix A · Resiliency scenarios

Multi-region resiliency scenarios

These examples show how service-specific regional behavior changes workload recovery design. They complement the broader customer scenarios in Section 08.

A workload in a nonpaired region requires DR

A workload operates in a zone-enabled region without a pair and must recover in another Azure region.

Storage
A supported region-of-choice pattern such as object replication where suitable, or application-level replication where required (for example, Data Lake Storage).
Compute
Azure Site Recovery for applicable VMs, or redeploy stateless compute from infrastructure as code.
Key Vault
Pre-provision the regional vault; runtime secrets, certificates, and any key strategy available before recovery.
Backup
Place backup and restore capabilities deliberately for the intended recovery region.
Takeaway. A nonpaired region can participate in a resilient multi-region architecture, but each workload layer needs an explicit recovery design.
“We’re paired, so we have DR”

Data is geo-replicated to the paired region, but the complete application has never been failed over and tested.

Symptom
Data is recoverable, but the application cannot operate in the secondary region.
Possible causes
Key Vault or another runtime dependency unavailable (failover not yet occurred, or read-only); DNS or private-endpoint configuration incomplete; compute or shared services not recoverable; dependencies missing from the recovery design.
Correction
Treat data, identity, secrets and keys, DNS, networking, shared services, and compute as workload dependencies. Validate end-to-end recovery against RTO and RPO.
Takeaway. Data recovery is not application recovery, and region pairing does not replace a tested workload recovery plan.
Customer-managed keys across two regions

A workload uses customer-managed encryption keys (for example, database TDE) and must operate or recover across two regions.

Constraint
Key material has different recovery and replication characteristics from secrets and certificates; it cannot be assumed to be recreated by the pipeline.
Options
Key Vault behavior for the selected regions (paired-region replication where available); backup and restore within the same subscription and geography; Azure Managed HSM multi-region replication; or another workload-specific design.
Validate
Key availability, access, private connectivity, permissions, and application behavior in the secondary region before the recovery path is considered complete.
Takeaway. Design key availability explicitly. For some workloads, key management determines which recovery regions are viable.
