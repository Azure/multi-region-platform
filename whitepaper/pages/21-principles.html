Profile selection

Principles for choosing and evolving a profile

  1. Start with the workload requirements and dependencies identified during regional qualification, including application-portfolio dependencies and relevant architecture characteristics.
  2. Use Workload Landing Zone archetypes as a planning abstraction to identify recurring connectivity and shared-service requirements; validate the selected profile against actual workload requirements.
  3. Select the most efficient regional connectivity profile that satisfies the identified requirements.
  4. Keep capabilities remote when latency, dependency, data, security, resiliency, availability, and operational characteristics permit. Deploy capabilities locally only when a measurable workload or platform requirement justifies the additional footprint.
  5. Consider direct spoke-to-spoke connectivity where workloads require significant east-west communication and a hub transit path is unnecessary. Introduce regional routing, inspection, or shared services when broader requirements justify them.
  6. Allow different profiles to coexist across the estate. Profiles evolve only when workload and platform requirements change, not because a region is expected to progress through a predefined maturity path.

A connectivity profile defines the platform capabilities available in a region. Workload placement, profile evolution, and future qualification remain separate decisions.
