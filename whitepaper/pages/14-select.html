This step is a set of decisions, not a deployment. For each qualified region, you decide what the platform provides there. Nothing is built yet: deployment follows later, through the automation you already run.

You make three decisions. Each follows from the workloads you expect in the region, not from the footprint of an existing hub. Start with the matrix (Figure 13, page ) to see which connectivity profiles each archetype typically uses. Then apply the selection principles and use the decision tree to pick the most efficient profile that meets the requirements.

Selection principles and decision treepages –

The three decisions sit on one path, from on-premises locations to the workloads in the region. They influence one another, but each has different requirements and tradeoffs. Connectivity that is specific to one application isn’t decided here. It is designed when the workload is placed (Part 4).
